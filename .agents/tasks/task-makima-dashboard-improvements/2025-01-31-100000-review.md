# MAKIMA dashboard improvements: back button, HINTER MT menu, coding system prompt

This change adds three independent features to the MAKIMA AI dashboard. A "KEMBALI" (back) button on the password-gate screen lets users return to the downloader without guessing the password. A new "HINTER MT" item appears in the side drawer as a coming-soon placeholder. The Gemini system prompt gains explicit coding-assistance capabilities and safety boundaries that refuse malware/phishing/hack requests. All three features are purely additive; the TikTok downloader logic is untouched and API keys remain environment-sourced.

**Watch for:** Back button positioning relies on `position: absolute` inside a parent that lacks `position: relative` (confirmed). The system prompt safety filter is purely LLM-instruction-level enforcement with no server-side validation (confirmed).

## High-level view

The back button wires an `onclick="showMainView()"` handler on an absolutely-positioned element inside `makima-password-gate`. The positioning concern is real but limited to the password-gate context where the parent is a full-viewport flex container—the button may anchor to the nearest positioned ancestor above it rather than the gate div.

HINTER MT is a textbook addition following the existing coming-soon pattern: a drawer item in `index.html` with `data-feature` attribute, a `viewConfig` entry typed as `coming-soon`, and a parallel `featureMap` entry. No new code paths, no API calls.

The system prompt expansion adds coding-assistant persona over a defined technology set and refusal instructions for dangerous requests. The safety boundary is client-trust-only—the LLM can be jailbroken and there is no server-side output filtering or classification.

## Back button and positioning gap

The back button HTML is injected as the first child inside `.makima-password-gate` in `_renderPasswordGate()`:

```html
<button class="makima-back-btn" onclick="showMainView()">← KEMBALI</button>
```

The CSS positions it with `position: absolute; top: 24px; left: 24px`. For this to anchor correctly within the gate, the parent (`.makima-password-gate`) needs `position: relative`. The existing rule is:

```css
.makima-password-gate {
  display: flex;
  align-items: center;
  justify-content: center;
  min-height: 100vh;
  /* no position property */
}
```

Without `position: relative`, the button anchors to the nearest positioned ancestor higher in the DOM tree. Because the gate is a full-viewport flex container, the button likely ends up approximately top-left of the viewport, but this is fragile—any future wrapper with `position: relative` would change the anchor point unexpectedly.

## System prompt safety is instruction-level only

The enforcement is entirely within the LLM prompt. There is no server-side check on the model's output before it is streamed back to the client. A determined user can craft jailbreak prompts to bypass system-instruction-level safety. If this boundary matters beyond UX (e.g., the app is publicly accessible and abuse is a concern), a secondary classification pass or output filter on the server would be necessary.
