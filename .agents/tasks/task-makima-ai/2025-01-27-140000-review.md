# MAKIMA AI chat feature with Gemini backend

A new sidebar-accessible chat page ("MAKIMA AI") is added to the MII NETWORK site. The frontend builds a chat interface client-side and POSTs user messages to `/api/ai-chat`, which proxies them to the Gemini 2.0 Flash model with a fixed persona system prompt. Rate limiting (3s per IP), missing-key fallback, and generic exception handling are included. The integration follows the existing view-switching and rate-limiting patterns cleanly.

**Watch for:** The Gemini client is re-configured on every request (confirmed), chat history is never sent so the model has no conversational memory (confirmed), and user input is forwarded directly into the generative model without sanitization or output filtering (confirmed).

## High-level view

The backend endpoint reconfigures the `genai` module and re-instantiates the model on every single request. Because `genai.configure()` is module-global and the app runs under gunicorn with threads, two concurrent requests race on shared module state.

The chat has no memory. Each request sends only the current user message with the system prompt; the model cannot reference anything said earlier in the conversation. This contradicts the "character assistant" framing where users might expect continuity.

User messages pass through to Gemini unmodified. There is no input length limit, no prompt-injection mitigation, and no output filtering. The system instruction asks the model not to discuss API keys, but that constraint is entirely enforced by the model's compliance with the system prompt, which is bypassable.

The frontend rebuilds the entire chat DOM on every navigation into the view, which means chat history is lost whenever the user switches away and back.

## Gemini client lifecycle and thread safety

The endpoint calls `genai.configure(api_key=api_key)` and instantiates a new `GenerativeModel` on every request (app.py lines 1303–1311). `genai.configure()` sets module-level state in the `google.generativeai` package. In a gunicorn worker with threads, two concurrent requests execute `genai.configure()` on the same module object. Today there's only one API key so the practical impact is limited to wasted work, but this is architecturally fragile — the typical pattern is to call `genai.configure()` once at module load (guarded by `if api_key`) and instantiate the model at that point, reusing it across requests.

## Input handling and prompt injection surface

The endpoint validates that `message` is non-empty but does not enforce a length limit. A client can POST megabytes of text, which gets forwarded to Gemini, burning tokens and potentially hitting upstream limits that return opaque errors. More critically, the user's message is the sole content passed to `model.generate_content(message)`. Adversarial prompts like "Ignore all previous instructions..." target the system prompt boundary. The system instruction says not to discuss API keys or internals, but compliance is probabilistic — there is no server-side sanitization, truncation, or output post-processing.

```python
# Current: no length check
message = data.get('message', '').strip()
if not message:
    return jsonify({'error': 'Pesan tidak boleh kosong'}), 400
# Goes straight to Gemini
response = model.generate_content(message)
```

Adding `if len(message) > 2000: return jsonify({'error': '...'}), 400` would cap the abuse surface cheaply.

## Chat state and conversation memory

The frontend's `renderMakimaAI()` wipes the view container's `innerHTML` every time the view is navigated to:

```javascript
container.innerHTML = '<div class="makima-ai-page">...'
```

This destroys all previously rendered chat bubbles. A module-level array holding message history, checked before re-rendering, would preserve continuity within a session.

On the backend, `generate_content(message)` sends a single user message with no prior context. The Gemini API supports multi-turn via `chat = model.start_chat(history=[...])` but none of that machinery is used. Each request is stateless, so the model cannot follow up on earlier answers.
