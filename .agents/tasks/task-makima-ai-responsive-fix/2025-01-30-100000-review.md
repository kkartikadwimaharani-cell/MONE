# Makima AI chat: silhouette removal and responsive layout overhaul

The Makima AI chat page gets a full-width, mobile-first responsive treatment. The anime body silhouette background element is removed from the DOM and hidden via multiple CSS layers as defense-in-depth. The mobile layout converts to a ChatGPT-style drawer sidebar (off-screen by default, slides in on toggle), while desktop gets a sticky sidebar always visible. The input area gains safe-area-inset padding for iPhone notch handling, and all avatar box-shadows are unified to a stronger glow.

**Watch for:** The header avatar jumps from 56px default to 40px on mobile, making the compact header disproportionately tall on desktop for a 50px-high bar (confirmed). The silhouette is removed three separate ways (HTML removal, `display:none` in animations.css, `display:none` in makima-ai.css) — the CSS rules are dead weight now that the DOM element is gone (confirmed). The `!important` density throughout is high and may create specificity debt for future changes (confirmed).

## High-level view

The silhouette removal is belt-and-suspenders: the DOM element is deleted from `index.html`, but two CSS rules still hide `.anime-body-silhouette` in case the element is re-introduced or cached. This is defensive but leaves dead CSS that will confuse future maintainers who won't find the element it targets.

The responsive split hides the sidebar off-screen as a fixed drawer on mobile, pins it sticky on desktop. The view-container override strategy uses `!important` on width, max-width, margin, and padding in three separate locations (base makima-ai.css, the mobile media query, and responsive.css). This triple declaration creates a maintenance trap where any future layout change requires hunting all three locations.

## Header avatar overflow on desktop

The `.makima-header-avatar` is set to 56×56px in the base rule and the desktop media query. The `.makima-compact-header` has `height: 50px; min-height: 50px`. A 56px avatar with a 2px border (60px total) inside a 50px container will overflow vertically.

```css
/* makima-ai.css base */
.makima-header-avatar {
  width: 56px;   /* <-- larger than container height */
  height: 56px;
}

.makima-compact-header {
  height: 50px;
  min-height: 50px;
}
```

Since `.makima-compact-header` doesn't set `overflow: hidden`, the avatar will visually protrude above and below the header bar on desktop.

## Silhouette removal: defense-in-depth vs dead code

The HTML element is removed from `templates/index.html` — this is the authoritative fix. Two additional CSS rules hide it:

1. `animations.css`: `.anime-body-silhouette { display: none !important; }` — added at the top of the existing rule block, which still contains ~30 lines of positioning, sizing, keyframe animations, and child element styles for an element that no longer exists.
2. `makima-ai.css`: `body.makima-ai-body .anime-body-silhouette { display: none !important; }` — scoped to the AI page only.

The `animations.css` approach of adding `display: none` to the top of a large existing style block creates confusion: future developers will see elaborate styling for a nonexistent element, with only the first line explaining it's dead. The silhouette-related responsive media queries in `responsive.css` were correctly removed (38 lines deleted), but the base `animations.css` block remains as orphaned code.

## `!important` proliferation on view-container

The `#viewMakimaAI.view-container` sizing appears in:

1. **makima-ai.css (base):** `max-width: 100% !important; width: 100% !important; margin: 0 !important; padding: 0 !important;`
2. **makima-ai.css (mobile @media):** same four properties with `!important`
3. **responsive.css (mobile master override):** `.makima-ai-page { width: 100% !important; max-width: 100% !important; padding: 0 !important; }`

All three fire on mobile. The base rule already covers all viewports, making the mobile media query redeclaration and the responsive.css override purely redundant. Any future attempt to add responsive padding (e.g., for tablets) would require overriding three locations.

## Desktop sidebar sticky positioning

The desktop media query sets `position: sticky; left: 0; top: 0` on `.makima-sidebar`, overriding the mobile `position: fixed; left: -280px`. The sticky behavior depends on the base rule's `height: 100vh; height: 100dvh` — without that explicit height in a flex row, the sidebar would stretch to content height and sticky would have no effect. This coupling isn't documented and could break silently.
